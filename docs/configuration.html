Configuration

On this page
  • Settings you should always look at
  • Configuration keys at a glance
  • No license key
  • Hiding the API server on the login page

Every setting works as in upstream Vikunja: it comes from config.yml or from an environment variable, and the environment variable wins. This page covers what the fork adds. For the generic settings (database, mail, authentication, CORS, rate limits and so on) see upstream's configuration options; they are upstream's documentation and describe upstream's releases.

The complete, current list of keys with their comments is config-raw.json in the repository. config.yml.sample is generated from it, so the JSON is the file to read.

Settings you should always look at #

These are upstream keys, but a working install of the fork depends on them:

KeyWhy it matters
service.publicurlThe address people use. Links in e-mails and incoming webhook addresses are built from it.
service.secretSigns tokens. If it is unset, a random one is created at every start and all tokens become invalid on restart. Encrypted project secrets of automation rules depend on it as well.
service.ipextractionmethod, service.trustedproxiesWhich client address the server uses. The per-IP limits of public forms and webhooks rely on it. See behind a reverse proxy.
database.type and the other database.* keysSQLite by default; PostgreSQL is the other tested choice. MySQL and MariaDB are compatible by design but not tested. See choosing a database.
files.basepathWhere attachments are stored. The image sets the root path to /app/vikunja/.

Configuration keys at a glance #

Settings come from config.yml or from environment variables; environment variables override the file. The variable name is VIKUNJA_ plus the key in upper case with dots as underscores, so automation.ticker.interval is VIKUNJA_AUTOMATION_TICKER_INTERVAL. The full list with comments is config-raw.json. config.yml.sample is generated from it with mage generate:config-yaml; edit the JSON, not the sample.

The modules without keys of their own (custom fields, workflows, approvals) share the instance's database and file settings. Besides these keys, service.publicurl, service.secret, service.timezone, service.ipextractionmethod, service.trustedproxies, outgoingrequests.allownonroutableips and outgoingrequests.proxyurl come from upstream and are used by the fork as described on the module pages.

No license key #

Upstream gates a few optional features behind license.key. In this fork nothing reads the key, so the setting has no effect even though it is still listed in config-raw.json.

Hiding the API server on the login page #

The login, registration and password reset pages of the web frontend show the API server they talk to, with a link to change it. When the frontend is only ever used with this instance (for example a single OpenID Connect provider and auth.local.enabled: false), turn the line off:

service:
  showapiconfig: false

or VIKUNJA_SERVICE_SHOWAPICONFIG=false. The default true keeps upstream's behaviour. The value is published as show_api_config in /api/v1/info and /api/v2/info. The desktop app is not affected: it shows the server once one was chosen. The error page shown when the frontend cannot reach the API keeps its address field, so a wrong address can still be fixed.
